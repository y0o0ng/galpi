# 6.1 Sol 통합 카드뉴스 제작 — 현재 정본

2026-10-10 한 편의 비교 시험을 수용해 앞으로의 기본 제작 흐름으로 채택했다. 폴더명은 기존 실행의 참조 경로를 보존하기 위해 유지한다. 과거 실행 원본과 모델·검토 기록은 변경하지 않는다.

Luna 후보 생성(최근7일, 일반인2/실무자1) → Luna 화제성 근거 확인 → 사람 선택 → 대본+카드 생성 → 독립 출처·문구 검토 → 독립 시각 검토 → 필요 수정 → 영향받은 독립 검토 재호출.
후보 탐색·화제성 확인은 `gpt-6-luna`, 제작·출처·시각·수정은 `gpt-6.1-sol`이며 reasoning effort는 `medium`이다. 후보는 candidates_cards.md와 verify_attention_cards.md, 이후는 create.md/review_sources.md/review_visual.md/fix.md를 치환해 독립 CLI 세션으로 실행한다. 정확한 호출 인자·시간·산출물 해시를 보존한다.

제작은 한 장 렌더→원본/390px 직접 열기→자가 검토/수정→다음 장 순서이며 self-review.md에 실제 확인 근거를 남긴다. 템플릿은 출발점이고 편 전용 콘텐츠 코드에서 구도·크기·분할·타이포그래피를 조정할 수 있다. 던파체 원본 비율·본문 Pretendard·팔레트·1080×1350 규격을 유지하며 공용 파일은 읽기 전용이다.
헤더/푸터는 콘텐츠 자유도에서 제외한다. 공용 Renderer.frame의 형태·위치·크기·폰트·색을 유지하며 카테고리·페이지번호/장수·확정날짜·출처 값만 동적으로 반영한다. 서버는 최종 합성에서도 같은 프레임을 강제한다.
사진과 픽셀 도식을 내용의 역할에 따라 혼합한다. 도움이 되는 실제 제품/현장 사진을 찾아보고, 정확한 대상·원URL·사용 조건·캡션을 assets.json에 남긴다. 사진을 강제로 픽셀화하거나 사용할 수 없는 사진을 억지로 추가하지 않는다.

출처 검토는 텍스트 원고/게시 문구/캡션/원문 및 사진 출처 메타데이터만 받는다. 사실관계·조건·문장·정보 누락·후킹을 검토하고 이미지·그림·사진·폰트·글자크기·배치·가독성 등 시각 요소는 평가하지 않는다. 시각 검토는 전 원본/390px 축소본을 실제로 열고 지나치게 큰 글자·정보 밀도·배치·사진·도트·헤더/푸터·가독성을 판단한다. 자가 검토는 독립 검토를 대체하지 않는다.

MUST 수정은 최대2회다. 문구·사실·의미·캡션·사진출처 조건이 바뀌면 출처 검토, 이미지가 바뀌면 시각 검토를 다시 호출한다. 둘 다 현재 산출물에 묶인 PASS여야 완료다. 통과하지 못하면 남은 문제와 함께 실패로 보고한다. 후보 선택과 최종 게시 승인은 사람이 한다.

후보·편집·미감 판단은 해당 독립 모델이 한다. 개발자는 실행 경계·문구/캡션 일치·출처 대조 도구·해시·규격·저장을 확인한다. 새 생성은 이전 편의 대본/그림을 입력하지 않으며 재시도는 검증된 현재 편의 산출물과 진행 기록을 사용한다. DB/API/승인/게시 스냅샷 경계는 기존 pipeline.md를 유지한다.

화제성은 최근7일의 실제 보도/게시글/반응 근거를 확인하고 제한된 검색의 최소 건수로만 기록한다. 전체웹 총량이나 검색순위를 인기도로 쓰지 않는다. 같은 기사재배포·같은URL/글·공식홍보를 독립기사로 중복 집계하지 않는다. 미확인과 반응0은 구분하며 선택 목록에는 verified 후보만 제공하고 weak·unverified는 원본과 제외 이유를 보존한 뒤 제외한다. 통과 후보가 일반인2·실무자1에 못 미치면 빈 슬롯을 최초 탐색 후 최대3회 재탐색한다. 통과분 유지·중복 방지·기존 검색 예산을 적용하고 목표 충족 시 종료한다. 재시도 소진 뒤에는 부족 이유와 확인된 후보만 보여준다.

게시 운영은 Instagram·YouTube 모두 수동이다. 완성본의 캡션·순서대로 JPEG 다운로드를 제공하고 자동 게시 큐는 사용하지 않는다.

최종 단계 완료는 `response.json`의 고정 `{"status":"ok","message":"..."}` / `{"status":"blocked","message":"..."}`만 사용한다. CLI JSON 스키마와 서버 검증을 함께 적용한다. create/fix 프롬프트에 정확한 JSON 틀을 명시하며 report.md는 설명용이다. Markdown의 READY_FOR_REVIEW/BLOCKED 표기·장식은 완료 판정에 사용하지 않는다.
