# 작업 지시: XION Reels {{episode}}편 도트판

저장소 `{{repo}}`. 앞 편 도트판들이 `reels/episodes/*_px/`에 있다. **이번 편은 확정된 대본으로 장면을 직접 설계하고 그린다.** 대본은 문장과 근거만 정해 두었다 — 무대·카메라·그림 구성은 네가 정한다. 앞 편은 코드 구조(엔진 사용법·`Episode`·부품)의 기준일 뿐 연출의 기준이 아니다. 조형·연출 기준은 제작 스킬 Part 1·2다.

## 먼저 읽을 것
1. **확정 대본(유일한 내용 정본): `{{final_path}}`** — 훅 카드, 오늘의 원리·배경음악, **장면 | 내레이션 | 근거 행** 표, 사실 확인 목록, **제작 제약**(그림이 틀리면 안 되는 조건, 그리면 안 되는 것, 화면 글자 목록, 뜻 있는 효과음). **문장·훅·원리·배경음악·장면 이름과 순서를 바꾸지 않는다.** 화면 글자는 화면 글자 목록에 있는 것만 쓴다. 그림으로 안 되는 게 있으면 바꾸지 말고 보고서에 적는다.
2. **`reels/px/skills/xion-pixel-art/SKILL.md`(Part 1 조형·Part 2 연출) 전부와 `reels/px/skills/xion-pixel-art/references/production-contract.md`(화면·자막·시간·소리·엔딩·엔진 API) 전부.**
3. `reels/px/templates.py`, `reels/px/timeline.py`와 앞 편 도트판 `scene.py`·`art.py` — 구조 기준.

## 순서
1. 확정 문장을 `{{repo}}/reels/.venv/bin/python {{repo}}/reels/px/secs.py "문장" "문장" …`으로 다시 확인한다(모든 조각 `PASS`·종료 코드 0). 실패하면 문장을 고치지 말고 보고한다.
2. **장면 설계**: 장면마다 무대(바탕 포함)·카메라(고정이면 고정)·진행 중인 과정(원인 → 결과)·핵심 장면을 정한다. 설계는 보고서에 짧게 쓰고 따로 긴 문서를 만들지 않는다.
3. 코드 → 렌더 → 프레임 → 보고서.

## 만들 것
`reels/episodes/{{episode_dir}}/` — `narration.ko.json`(훅 제목·부제와 장면별 문장, 대본 표의 글자 그대로. 대본의 `오늘의 원리`를 **`"principle": [줄1, 줄2, 줄3]`와 `"principle_label"`(영문 라벨, 대본에 있을 때만)로 그대로 옮긴다**. 대본의 배경음악은 `"bgm": "bright"|"calm"|"tense"`로 옮긴다), `scenes.json`(장면 순서와 연출에 필요한 최소 길이), `art.py`(이 편 그림), `scene.py`(`Episode` 실행기, 연출은 `at(T, 문장번호, 비율)`로 문장에 묶되 시작 신호로만 쓴다). 출력 `reels/media/{{out_name}}.mp4`.

- **엔딩 "오늘의 원리" 도장 장면은 엔진이 `principle`을 보고 마지막 장면 뒤에 자동으로 붙인다. 그리지 않는다.** 장면 목록·`DRAW`에 넣지 말고, 마지막 장면은 대본대로 그대로 둔다. `principle` 줄이 폭을 넘으면 엔진이 멈추니 대본을 고치지 말고 보고하라.
- 카드 분할은 엔진이 한다. 한두 마디만 혼자 뜨는 꼬리 카드가 생기면 쉼표 뒤 공백 자리에만 ` / `를 넣을 수 있다(글자는 그대로). 넣은 자리를 보고.
- 하단 자막은 갈무리11 Regular 12px·내부 폭 148px·최대 두 줄이다. 실패한 원고는 글자 축소·공용 템플릿 수정으로 숨기지 말고 보고한다.
- **공용 코드 `reels/px/`는 읽기 전용이다.** 새 배치·부품·효과음이 필요하면 이 편 폴더 안(`art.py`·`scene.py`)에서 만든다(효과음은 `audio.sfx`와 같은 방식 — 사인파, 낮은 피치, 둥근 엔벌로프 — 로 편 안에서 합성해 섞는다). 여러 편에 쓸 만하면 보고서에 적어라 — 템플릿으로 올리는 건 사람이 한다. **`templates.py`에 이미 있는 부품은 편 폴더에 다시 만들지 않고 import해 쓴다** — 문장·카드 시각 `cardt`, 12fps 깜빡 `blinking`, 점선 사각 `dotted_rect`, 단면도 확대 `cutaway`, 가리키기 `pointer`(`face="left"|"right"` — 시온이 대상 쪽을 보게, 대상의 오른쪽에 서면 left·왼쪽에 서면 right). 비슷하지만 모자라면 복사해 고치지 말고 보고서에 적어라. **사람 몸은 `px/figure.py`의 `figure`(반신상, 앵커)·`icon`(작은 얼굴)을 쓰거나, 손·손가락처럼 직접 그릴 때는 `PEOPLE_COLORS` 피부색으로 그린다**(`scheme="warm"` 주인공, `"muted"` 조연). 불은 `FIRE_COLORS`.
- **효과음은 `T.sfx`에 `(장면 시각, 종류, 역할)`로 단다**(역할 `motion`·`event`·`accent`, Contract 소리 절). 화면에서 동작·사건이 일어나는 순간마다 동작음·사건음을 단다 — 편당 개수 제한은 없다.
- 마스코트는 역할이 있을 때만(훅 놀람·핵심 지목·결론 반짝임), 카드 글자·화면 라벨을 가리지 않게. HUD·위 띠(`templates.hud`·`templates.band`)는 대본이 요구하지 않았으니 쓰지 않는다.
- **움직임 구현:**
  - 무대마다 편 폴더 안에 그리기 함수를 둔다(캔버스보다 커도 된다). 카메라는 무대를 잘라 보여 주는 함수이고, 움직일 때는 `timeline.tween`과 감속곡선으로 **출력 24fps 매 프레임 정수 도트씩** 움직인다(카메라에는 12fps `step`을 쓰지 않는다). 확대는 최근접 정수배만, 배율이 바뀌는 순간은 컷으로 넘긴다. 카메라는 이야기가 요구하는 곳에서만 움직이고 나머지는 서 있다.
  - 같은 무대에서 장면이 바뀔 때는 다음 장면 0초 화면이 앞 장면 마지막 화면과 이어져야 한다. 무대가 바뀌는 곳은 끊는다. 연결 문장(질문·다리 문장)이 카드에 떠 있는 동안에도 화면이 비지 않게 다음 무대를 미리 들이거나 앞 무대를 남긴다.
  - 진행 중인 과정은 장면 시간 `t`의 연속 함수로 그린다. 그림 속 움직임은 12fps로 끊는다(도트 느낌). 그림 영역(y 0~250)이 1초 넘게 완전히 얼어붙지 않게 하고, 메우는 것은 진행 중인 과정과 그 무대에 원래 있을 법한 작은 움직임이다. 카메라를 움직여 메우지 않는다.
- **그림 품질:** 제작 스킬 Part 1. 형태(비례·윤곽)를 먼저 맞추고 명암은 필요한 곳에만(모든 면 2단 의무 없음). 빌드에서는 프레임을 열어 보지 않으므로 조건부 기본형 프레임 확인은 하지 않고, 했다고 보고하지 않는다.
