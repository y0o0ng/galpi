## 후보 수집·선택 — 크롤러 정본 (2026-10-12)

정규 수집은 `lib/cards/crawler.js`가 기존 RSS parser를 재사용해 기술 매체·한국어 전자신문·Google/Google Developers/OpenAI/Microsoft/GitHub/Python 공식 피드 13개를 읽는다. 피드별 최대24개·최근7일 자료를 모으고 날짜 미확인은 명시한다. HN 검색으로 게시물을 발견한 뒤 공식 API에서 최대100개 게시물의 실제 score·descendants를 읽는다. 동시 HN 요청은6개로 제한한다. 원문 본문 전체를 전수 다운로드하지 않는다. 피드 절반 이상 실패 또는 자료20개 미만일 때만 공유 캐시·예산을 쓰는 Tavily 보충 검색2개를 실행한다. 특정 사건 검색어는 없다.

URL·확실히 동일한 제목만 코드로 묶는다. 다른 제목의 동일 사건은 별개로 남을 수 있으므로 코드가 보도 독립성이나 전체 인기 점수를 추정하지 않는다. 관측 기사 수·HN 게시물 수·해당 게시물 댓글/점수와 관측 매체 수를 분리하며 SNS 수와 독립 보도 수는 미확인(null)이다. 정상 API에서 확인한 0과 실패/미관측을 구분한다. 공개 반응이 없는 공식 발표도 내용 근거가 충분하면 선택 가능하다. 전체 수집 결과·소스별 성공/실패는 `crawler-*/collection.json`에 보존한다.

`selectCrawlerCandidates`가 compact 제목·피드 요약·URL·날짜 종류·코드 집계를 Luna medium에 한 번 전달한다. 읽기 전용·검색 비활성으로 선택만 수행한다. `select_crawled_cards.md`는 기술 자체의 변화가 명확한 소식만 선택하며 일반 생활/질병/여행 소식은 제외한다. 새롭게 가능한 일·독자의 궁금증·실제 효용을 우선하고 일반인2·실무자1을 선택한다. 서버는 선택 ID·수집 자료 URL·중복·대상 할당을 검증하고 선택한 사건 자료의 attention을 서버가 합산한다. 모델은 수치를 만들거나 수정하지 않는다. 정규 후보의 독립 화제성 LLM·재순위·15개 중간 후보 루프는 호출하지 않는다. 부족하면1개도 표시하고0개면empty·수집실패는failed다. 선택된 주제는 기존 제작 단계가 실제 원문을 확보해 출처를 검토한다. 이전 후보 프롬프트·실험 결과는 역사 재현용으로 보존한다.

선택 모델은 후보별 `same_event:[{id,reason}]`를 함께 반환한다. 기준 자료와 제목·요약에서 동일한 제품/버전·행동·시기/장소가 확인되는 사건 자료만 묶으며 같은 회사·분야의 다른 사건이나 일반 배경 자료는 제외한다. 비교 반대편 자료도 기준 사건 집계에는 넣지 않는다. 서버는 존재하는 ID·비어 있지 않은 이유·묶기 내 중복·후보 간 중복 배정을 검증한다. news의 최종 출처는 검증된 기준 자료를 먼저, same_event 순서로 최대 6개 구성하며 제목·URL·날짜도 수집 자료에서 가져온다. 모델이 따로 작성한 news sources는 최종 출처로 사용하지 않는다. HN 게시일·검색 추정일·네이버 제공일·날짜 미확인은 출처의 published_at을 null로 남기며 announced_at을 채우지 않는다. 묶음 밖 출처를 근거로 사건 ID를 자동 추가하지 않는다. compare 출처의 기존 수집 URL 검증은 유지한다. 기사 URL 추적 파라미터·중복 HN 게시물을 제거한 evidence에서 관측 수치를 다시 계산한다. 출처의 6개 제한과 달리 attention은 묶인 자료 전체를 집계한다. `attention.grouping`에 기준 ID·모델의 일치 이유를 보존한다. 사건 동일성은 모델 판단이지 코드로 검증된 사실이나 독립 보도 판정이 아니며 limits에도 명시한다. 별도 모델 호출·전수 사건 분류는 없다. 수집 자료·원본 응답·기존 후보는 그대로 보존하고 선택된 후보의 묶기만 집계한다.

19시 KST 회차 경계와3시 제작·사용자 선택·직접 제안 계약은 유지한다.

2026-10-12 동일533개 수집 자료의 격리된 Luna medium 비교에서 CCTV 후보는 기준 기사1개에서 같은 사건 기사3개·원문 도메인3개로 집계가 확장됐다(전자신문·동아일보·MS투데이). SynthID 공식 발표와 AWS AgentCore 보도에는 추가 자료를 묶지 않았다. 결과는 `/tmp/cards-event-preview-1791785192/crawler-*/result.json`이며 production DB·기존 후보는 변경하지 않았다. 선택+묶기1회 입력95,347·출력2,013토큰이고, 묶기 전 선택1회는93,765·1,256이었다. 이는 한 회차의 동작 확인이며 사건 동일성 정확도나 독립 보도 수를 입증한 전수 검토는 아니다. 구조·중복 제거·오류 거부 관련29개와 워커/회차3개 테스트가 통과했다.

### 네이버 국내 뉴스 보충

`NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`이 모두 설정된 경우 NAVER API HUB의 `https://naverapihub.apigw.ntruss.com/search/v1/news`를 사용하고 `X-NCP-APIGW-API-KEY-ID`·`X-NCP-APIGW-API-KEY` 헤더로 인증한다. 구형 Developers Center 주소·헤더는 API HUB 키와 호환되지 않는다. 인공지능·로봇·반도체·소프트웨어·사이버 보안·신기술 6개 검색어를 최신순으로 각50개 조회하고 제공 날짜가 최근7일인 기사만 합친다. 원문 `originallink`를 우선하며 제목·요약의 HTML 강조를 제거한다. `pubDate`는 원문 발표일이 아니라 네이버 제공 시각일 수 있으므로 `date_kind:naver_provided`로 남긴다. 전체 검색 건수 `total`은 기간 제한이 없고 반응 수치도 아니므로 사용하지 않는다. 여러 검색어에 걸린 동일 기사 URL은 기존 묶기에서 중복 제거한다. 관측 매체는 원문 호스트로 집계하고 독립 보도 여부는 추정하지 않는다. 인증 키가 없으면 `skipped/credentials_missing`, 조회 실패는 검색어별 `failed`로 기록하고 다른 소스는 유지한다. 키를 포함한 요청의 리다이렉트는 차단한다. 뉴스 검색을 켠 NAVER API HUB 앱과 서버 재시작이 필요하다. 데이터랩은 이번 범위에 포함하지 않는다.

## 직접 제안·수정 대화

주제 선정 화면에서 주제·링크 또는 수정 메시지를 입력한다. 대화 상태는 기존 app_settings의 `cards.manual_topic`에 보존하며 승인 대화는 `cards.manual_topic.<id>`로 보관한다. DB migration은 추가하지 않는다. 요청마다 id·revision을 대조하고 queued/reviewing 중 중복 요청을 거부한다.

worker가 제작 시간과 무관하게 Luna medium의 독립 세션을 호출한다. 검색·원문과 제안/수정 대화를 대조하고 사실·불확실성·수정 방향을 해요체로 설명한다. 입력 자료 URL과 실제 인용을 검증한다. `needs_revision`이면 피드백만 표시하고, 사실 확인 가능한 주제면 `ready`와 단일 후보를 표시한다. ready도 제작 승인은 아니다.

사용자가 현재 id·revision을 승인하면 별도 manual 배치와 후보를 만든 뒤 기존 selectCandidate 경로로 queued job을 원자적으로 생성한다. 승인 전에는 job이 없으며 수정 메시지는 이전 ready와 후보를 즉시 무효화한다. 재시작 중 reviewing은 피드백 상태로 복구하고 자동 승인하지 않는다. 승인된 작업은 새벽 3시부터 기존 통합 제작·검토 흐름을 따른다.

## 제작·검토 경계

- 내용 단계/순서는 독자의 질문에 맞게 정하고 각 단계1~2페이지. 뉴스4~7·비교4~8, cover/closing과 강한 근거 기반 후킹·해요체·일반 독자의 지식선을 유지한다. 제품의 정체·실제 기능·새로운 차이가 일반론/용어 정의에 밀리면 문구 검토에서 고친다.
- 후보 선택 후 queued, 03:00~07:00 KST에 한 편씩 시작하며 시작한 작업은 창이 끝나도 이어간다. 워커는 5분 간격으로 확인하므로 새벽 3시 이후 첫 확인에서 시작한다.
- create는 원고·deck·캡션·그림/사진·편 전용 렌더 코드를 함께 작성한다. 한 장씩 렌더→원본/390px 실제 열기→자가 검토/수정→다음 장, self-review.md에 실제 기록을 남긴다. 자가 검토는 독립 PASS가 아니다.
- 콘텐츠 구도·슬롯·크기·분할·타이포그래피는 편 전용 코드에서 유연하게 조정한다. 공용 파일은 읽기 전용. 던파체 원본 비율/Pretendard·팔레트·1080×1350·브랜드를 유지한다.
- 헤더/푸터는 자유도에서 제외하며 공용 Renderer.frame의 형태/좌표/크기/글꼴/색을 고정한다. 카테고리·번호/장수·확정날짜·출처 값만 바뀐다. 서버 finalize_integrated.py가 PNG 상단0~159/하단1240~1349를 공용 frame으로 합성하고 preview/mobile/JPEG를 동기화한다. 최종 합성 이미지를 독립 시각 검토에 넘긴다.
- 사진은 실물/현장 정보에 도움이 되면 사용한다. 원비율·정확한 대상·원URL·제공자·사용 조건·캡션을 assets.json에 남긴다. 사진을 강제 픽셀화하지 않고 비슷한 도트를 반복하지 않는다. 사진과 픽셀 자산 경로는 해당 편 안으로 제한한다.
- 출처 검토는 원고/게시 필드/캡션/원문/파일 경로가 없는 사진 메타데이터의 **텍스트 전용 패킷**을 받는다. 사실·조건·출처·문구의 의미/자연스러움/누락을 검토한다. 이미지/그림/사진/렌더 코드/글자크기/배치/가독성/헤더형태를 평가하지 않는다.
- 시각 검토는 현재 원고·모든1080원본/390px축소본을 직접 연다. 과도한 글자 크기·위계·줄바꿈·정보 밀도·여백·실사진/도식·가독성·고정 frame을 판단하며 예전 템플릿 숫자 크기 자체를 강제하지 않는다.
- source/visual은 보고서만 작성, MUST/NICE와 PASS/NEEDS_FIX/BLOCKED를 남긴다. 최대2회 MUST 수정 후 의미/문구/캡션/사진조건이 바뀌면 출처 검토, 이미지가 바뀌면 시각 검토를 새로 호출한다. 두 PASS가 현재 산출물 해시에 묶여야 완료다.
- 모델 제작 Python은 생성/fix의 Codex sandbox 안에서만 실행한다. 서버가 sandbox 밖에서 편 전용 Python을 직접 실행하지 않고 trusted finalize_integrated.py만 실행한다. 단계 작업 폴더 외 쓰기 허용·API키 전달·패키지 설치·운영 설정 변경은 하지 않는다.
- 서버는 manuscript의 조립 원고 JSON/deck/caption 일치, C주장·원URL·인용25자 대조, PNG/mobile/RGB JPEG장수/규격, 자산 경로·검토 파일 해시를 검사한다. 인용 존재는 의미적 정확성을 대신하지 않는다.
- 재시도/중단은 production.json 단계 기록과 스냅샷을 검증해 이어간다. 입력·프롬프트·브랜드 코드·폰트가 바뀌면 검토를 재사용하지 않는다. 수정이 시작된 산출물에는 이전 PASS를 적용하지 않는다.
