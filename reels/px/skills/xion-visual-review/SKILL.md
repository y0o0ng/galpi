# XION Independent Visual Review Skill

> **문서 상태:** 현재 독립 시각 검토 기준. MP4 기반 전처리 자료(시간순 시트·manifest)는 아직 없다 — 계획은 `docs/xion-pixel-skills-design.md`. `active`는 그 기능이 구현됐다는 뜻이 아니다.

## 목적

완성된 XION 도트 영상이 기술·과학 원리를 정확하고 설득력 있는 시각적 경험으로 전달하는지 **독립적으로 평가**한다.

목표는 가능한 한 많은 지적을 만드는 것이 아니다. 시청자가 실제로 보게 되는 결함을 찾아내고, 관찰 근거·원인·최소 수정 방향을 구체적으로 전달하는 것이다.

평가 대상은 정지 이미지의 집합이 아니라 **시간 속에서 진행되는 완성 영상**이다.

## 형식 2(애니메이션 중심 4px) 검토 기준

새 제작은 형식 2다(자막 카드 없음, 도트 4×4px, 글자는 승인 문구만 장면 안, 확장색은 역할별 선언). 아래 항목을 이 문서의 모든 절에 더해 본다. 형식 1(옛 5px) 영상은 기존 기준대로 본다.

- **4px 규격 유지:** 도트 크기가 섞이지 않았는지, 마스코트·부품이 4px 격자에서 정체성을 지키는지(마스코트가 20% 작은 것 자체는 결함이 아니다).
- **표현력 사용:** 늘어난 도트 해상도가 형태·구조·층 구별에 쓰였는지. 더 세밀하거나 색이 많을 수 있다는 이유만으로 MUST를 만들지 않는다.
- **한국어 가독성:** 진술·라벨·수치가 폰 화면 크기에서 읽히고, 잘리거나 겹치지 않고, 안전 영역 안에 있고, 충분히 오래 보이는가(최소 읽기 시간은 문구 길이로 판단).
- **글자와 움직임의 주의 경쟁:** 중요한 변화가 일어나는 순간 새 문구가 시선을 빼앗지 않는가.
- **애니메이션이 실제로 설명하는가:** 확정 대본의 제작 제약이 요구한 인과(방향·순서)가 문구 없이도 움직임으로 보이는가, 시각 과정이 정지 그림 교체가 아니라 진행으로 나오는가.
- **확장색:** 구별해야 할 것들이 색·형태로 구별되는가, 브랜드색과 조화되는가, 명도 차이로 묻히는 요소가 없는가, 같은 물체의 색이 장면 사이에 일관적인가, 색만으로 필수 정보를 구분하지 않는가. 범위 안이라는 기계 검사는 미적 승인이 아니다.
- **결과 확인 시간:** 변화의 결과가 이해될 만큼 머무는가.
- **하단 고정 자막 박스·일반 문구 타자기**가 본편에 있으면 계약 위반(MUST). 엔딩은 형식 1과 같은 구성이어야 한다.
- MUST는 정확성 오류·주요 정보 누락·명백한 가독성 결함·구조 오류·확정 계약 위반이고, 표현 개선 여지는 NICE다. **보지 않은 프레임을 검토했다고 주장하지 않는다.**

## 0. 검토자의 역할과 독립성

- 제작자는 아니며 소스 코드를 직접 수정하지 않는다.
- 확정 대본·제작 제약과 XION 제작 스킬의 Part 1/Part 2, Production Contract를 기준으로 판단한다.
- 실제 렌더 결과가 제작자의 의도·보고서보다 우선한다.
- 이전 편의 승인된 디자인은 크기·가독성·정체성 참고용이지 연출 복제의 정답이 아니다.
- 취향만으로 MUST를 만들지 않고, 고칠 것이 없으면 불필요한 지적을 만들지 않는다.
- 기존 `visual` 단계를 사용한다. 새 LLM 검토 단계, 중간 사용자 승인 단계는 추가하지 않는다.

## 1. 자료와 증거의 우선순위

현재 입력: 1. 제작 단계가 뽑은 PNG 프레임(장면 mid·end, 문장 카드, 장면 경계 `_last`/`_first`, 엔딩 도장 직후·마지막) 2. 확정 대본과 제작 제약 3. 제작 보고서(장면 설계·진행 중인 과정·효과음 kept/dropped) 4. 편별 코드(읽기 전용)와 렌더가 남긴 효과음 kept/dropped 5. 제작 스킬(`../xion-pixel-art/SKILL.md`)과 Production Contract. 승인된 이전 편 프레임은 크기·가독성 참고용이다. MP4 기반 전처리 자료가 제공되는 환경에서는 그것을 1순위 증거로 쓴다. 자료가 없다는 이유만으로 MUST를 만들지 않는다 — 실제로 본 결함과 증거 부족을 구분한다.

보고서에 '흐름이 이어진다'고 적혀 있어도 화면에서 확인되지 않으면 구현된 것으로 판단하지 않는다. 반대로 보고서에 없는 정상 움직임을 누락으로 단정하지 않는다.

시각 자료가 누락된 구간은 보지 않았다고 명시한다. 검토 자료 자체의 완전성 검사와 영상의 미적 품질 판단을 구분한다.

## 2. 시간 구간 검토

완성 영상의 전체 길이를 **빠짐없는 시간 구간**으로 살펴본다. 장면당 시작·중간·끝 프레임 세 장만으로 움직임 전체를 평가하지 않는다.

### 기본 전체 관찰

현재는 제작 단계가 뽑은 프레임과 보고서의 '진행 중인 과정'으로 시간 흐름을 판단한다. 프레임 사이 구간은 본 것이 아니다 — 프레임으로 확인되지 않은 움직임·멈춤은 확인 불가로 적는다. 검토자는 전체 무대의 전개, 장면 전환, 설명 흐름, 주인공의 위치, 변화의 존재 여부를 파악한다.

### 밀집 관찰

다음은 가능한 경우 기본 요약보다 촘촘한 연속 프레임으로 살펴본다.

- 원인→결과가 발생하는 핵심 순간
- 복잡한 인체·동물·기계의 움직임과 연결부
- 회전·변형·압축·충돌과 반복 사건
- 카메라 이동·확대·장면 경계
- 소리와 정확히 맞아야 하는 사건
- 기본 개요에서 이상이 의심된 순간

연속 프레임(12fps 일반·24fps 카메라)이 제공되지 않은 구간의 위 판단은 확인 불가로 남긴다.

### 판단 기준

- 원인이 먼저 작용하고 결과가 이어지는가?
- 변화가 진행 과정 없이 완성 그림으로 툭 나타나지 않는가?
- 자막 카드마다 움직임이 불필요하게 끊기지 않는가?
- 같은 무대의 끝·시작 상태가 연결되는가?
- 움직임 속도·시간·지속이 이해에 맞는가?
- 카메라가 의미 없이 움직이거나 픽셀이 버벅이지 않는가?
- 주인공이 변하지 않는데 배경 깜빡임으로만 '움직임'을 채우지 않는가?
- 엔딩을 제외한 그림 영역이 1초 넘게 실제로 얼어붙은 구간이 있는가?

프레임 차이 분석은 보조 자료다. 픽셀이 변했다는 사실만으로 의미 있는 움직임이라고 판정하지 않는다.

## 3. 픽셀아트와 조형 검토

조형 문제는 다음 순서로 진단한다. 상위 단계의 오류를 명암이나 장식 디테일로 가리려 하지 않는다.

### ① 정체성 — 무엇인지 알아보이는가?

핵심 대상이 다른 사물로 읽히지 않는지, 고유 실루엣과 기능적 특징이 남아 있는지, 영상 크기에서 충분히 크게 보여지는지 확인한다.

### ② 비례 — 주요 부분의 크기와 위치가 맞는가?

인체의 머리·몸통·팔다리·관절과 손바닥·손가락의 길이·방향, 기계 본체·부품·축의 비례를 확인한다. 의도적 단순화와 과장은 허용하되 실제 구조나 원리를 왜곡하면 결함이다.

### ③ 구조 — 올바르게 연결되어 있는가?

접촉·연결·포함·앞뒤·안팎 관계를 확인한다. 움직임 중 관절과 축·부품 연결점이 비정상적으로 분리되거나 다른 위치로 점프하지 않는지 연속 프레임에서 살펴본다.

### ④ 명암과 깊이 — 입체감이 설득력 있는가?

광원·면 방향·부피·공간적 깊이가 읽히는지 판단한다. 명암이 오히려 윤곽을 흐리거나 구조를 왜곡하면 문제다. **모든 면의 명암 2단 부재는 결함이 아니다.** 단색 면이 더 명료할 수 있다.

### ⑤ 픽셀 품질 — 화면이 정돈되어 있는가?

불필요한 고립 픽셀·불규칙한 계단·들쭉날쭉한 선·과밀 디테일·의미 없는 디더·팔레트 의미 오류·혼합된 픽셀 크기를 확인한다. 설명에 도움되지 않는 디테일이 적다는 이유로 지적하지 않는다.

**조형 진단 우선순위: 정체성 → 비례 → 구조 → 명암 → 픽셀 품질.**

## 4. 공간과 아트 디렉션 검토

- 대상이 실제 환경·내부 단면·추상 도식 중 적절한 무대에서 설명되는가?
- 주요 물체와 주변 구조의 관계가 이해되는가?
- 지금 중요한 변화가 가장 먼저 눈에 들어오는가?
- 배경과 보조 요소가 시선을 빼앗지 않는가?
- 핵심 장면에는 충분히 표현력이 집중되고, 보조 장면은 필요에 따라 단순한가?
- 도입·내부 설명·결과가 하나의 이해 흐름으로 이어지는가?
- 관찰 대상이 바뀔 때 공간 전환을 이해할 수 있는가?
- 연결 질문이 표시될 때 무대가 비어 있지 않은가?

고정 카메라·단순 카드·서로 다른 무대 사이 컷은 그 자체로 결함이 아니다. 주제에 적합한 연출인지 판단한다.

## 5. 대본·화면·기술 계약 검토

- 해당 문장과 화면의 사건·방향·순서가 맞는가?
- 핵심 구조·수치·색의 의미가 확정 근거와 맞는가?
- 제작 제약의 금지 표현과 화면 글자 목록을 지키는가?
- 자막·라벨이 잘리거나 가려지지 않고 폰 화면에서 읽히는가?
- 마스코트·HUD·소주제 위 띠가 필요한 조건에 맞게 쓰였는가?
- `principle`·라벨·도장과 엔딩 프레임이 정상인가?
- 팔레트와 출력 픽셀 규격의 기계 검사 결과는 정상인가?
- 동일한 물건의 색·비례·연결 관계가 편 안에서 일관적인가?

이미 엔진의 lint가 확정적으로 검사한 사항은 해당 검사 결과를 활용하되, 렌더 통과가 곧 시각적 완성도 통과라는 뜻은 아니다.

## 6. 효과음의 기계적 검토

미적 청감이나 음색 취향을 판단하지 않는다. **실제 렌더된 화면 사건**과 **실제로 채택된 효과음의 시각·역할**을 대조한다.

- 동작음이 동작의 시작·변화·종료에 대응하는가?
- 반복 사건과 사건음의 주기가 맞는가?
- 중요한 사건음이 누락되거나 잘못된 시각에 발생하는가?
- 강조음은 기존 최소 2초 간격을 지키는가?
- 동작음·사건음에 강조음 간격 제한이 잘못 적용돼 누락되지 않았는가?
- 불필요한 중복·겹침·끝난 뒤의 소리가 있는가?
- 엔딩 `jingle`·`stamp`가 누락되지 않았는가?

제작 보고서의 '예정' 효과음과 믹서가 실제 채택한 이벤트를 구분한다. 실제 오디오 파형을 듣지 않는 검토 방식에서는 **청감까지 검증했다고 주장하지 않는다.** BGM 세 곡과 기존 음향 디자인은 재평가하지 않고, 최종 청감은 사용자 영상 승인에 포함한다.

효과음 정보는 렌더 로그와 보고서의 kept/dropped(시각·종류·역할)다. 역할 없이 들어간 템플릿 소리(훅 `pop`·`sparkle`)는 역할이 찍히지 않는다.

## 7. MUST / NICE 기준

### MUST

시청자에게 명백하게 보이는 결함, 중요한 원리의 오해, 확정 계약 위반이다. 예: 다른 물건으로 읽히는 핵심 실루엣, 붕괴한 관절·기계 연결부, 반대로 그려진 인과관계, 진행 중 변화가 갑자기 완성되는 화면, 이해를 방해하는 장면 불연속, 읽을 수 없는 자막, 실제 사건과 어긋난 효과음.

### NICE

지금도 원리가 올바르게 전달되지만 개선 여지가 있는 경우다. 예: 조금 부자연스러운 비례, 공간감 개선, 불필요한 디테일 제거, 리듬 조정. 단순 취향 차이·더 복잡한 그림 선호는 지적 사유가 아니다.

검토 자료가 누락되어 판단하지 못한 항목은 **확인 불가**로 적는다. 빌드 완료 조건이 요구한 프레임(예: 엔딩 도장 직후·마지막)이 폴더에 없으면 빌드 계약 위반으로 MUST다. `MUST 0`으로 완료한 척하지 않는다.

## 8. 문제 보고 방식

문제마다 다음을 기록한다.

- `[MUST]` 또는 `[NICE]`
- 장면, 실제 영상의 시각 또는 구간
- 관찰한 현상과 근거 프레임/시트
- 그 현상이 시각적·과학적으로 왜 문제인지
- 원인으로 의심되는 구조·레이어·타이밍 (불확실하면 가설이라고 명시)
- 가장 작은 수정 방향
- 수정 후 재확인할 시간 구간/프레임

예: `[MUST] 00:18.2–00:19.1 — 손가락 가운데 관절 연결이 접히는 중 분리되어 보임. 관절 앵커와 양쪽 마디 연결 관계를 먼저 수정하고 해당 구간 연속 프레임 재확인. 명암 추가는 해결책이 아님.`

정확한 위치를 알 수 없는데 임의의 좌표나 픽셀 이동량을 지어내지 않는다.

## 9. 보고서 형식과 파이프라인

기존 `visual_review.md` 형식을 유지한다.

1. 첫 줄은 정확히 `MUST n / NICE m`.
2. 검토한 프레임 범위와 미검토 구간을 명시한다.
3. 발견한 MUST/NICE 항목의 관찰 근거와 수정 방법을 작성한다.
4. 문제가 없었던 주요 계약의 확인 근거와 짧은 전체 평가를 남긴다.
5. 확인할 수 없었던 영역과 이유를 기록한다.

검토자는 읽기 전용으로 편별 코드를 볼 수 있지만 코드를 수정하지 않는다. 기존 `visual` 단계의 MUST만 `fix`에 전달한다. NICE는 자동 수정하지 않는다. 수정 후 영향을 받은 구간과 장면 경계를 다시 검토한다. (현재 자동 제작에는 fix 뒤 재검토가 없고, 사람 의견 수정 경로 `reviseEpisode`에서만 visual이 다시 돈다.)
